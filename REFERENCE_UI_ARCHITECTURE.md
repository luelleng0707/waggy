# REFERENCE_UI_ARCHITECTURE

## Application shell
- `QApplication` bootstrap in `app.py` creates native desktop shell.

## Root layout
- `MainWindow` with left sidebar menu + right stacked content area (`ui/main_window.py`).

## Navigation implementation
- `QListWidget.currentRowChanged` -> `QStackedWidget.setCurrentIndex`.

## Page switching
- Index-based switching in `MainWindow._switch_page`.

## Reusable component structure
- Reusable card/section helper methods in `ui/dashboard.py`:
  - `_create_stat_card`
  - `_create_section_card`

## State location
- User/session state lives on window instances (`current_user`).
- No centralized application store.

## Page data request path
- Page method calls `db_manager.get_session()` and performs inline ORM queries.

## Loading/error handling
- Login flow toggles button disable/loading text.
- Errors shown via labels and `QMessageBox`.

## Forms
- Login form with `QLineEdit`, `QCheckBox`, `QPushButton`.

## Tables
- No table abstraction found in implemented pages.

## Charts
- No chart implementation in active UI code despite descriptive comments.

## Modals/drawers
- `QMessageBox` used for confirm/info/error dialogs.

## Detail pages
- Not implemented as dedicated reusable detail-page framework.

## Dashboard cards
- Generated by helper methods in `DashboardWidget` and updated via key lookups.

## Filters
- No generalized filter subsystem found in active pages.

## Notifications
- Dashboard reads `Notification` rows and renders labels in a list-like section.

## API response -> UI state transformation
- No HTTP API in CSTC_1524; ORM result objects are transformed directly into label text and simple sections.

## Three complete source-backed flows

### Flow 1: App startup
1. User executes `python app.py`
2. `QApplication` created
3. DB tables checked/created + seed routines
4. `LoginWindow` shown

### Flow 2: Login success
1. User clicks login button
2. Input validated in login widget
3. SQLAlchemy lookup on `User`
4. Password verified with bcrypt
5. Audit `SystemLog` persisted
6. `MainWindow` opened with `current_user`

### Flow 3: Dashboard data render
1. `MainWindow` constructs `DashboardWidget`
2. `DashboardWidget._load_data()` opens DB session
3. Aggregate queries (customers/pets/appointments/revenue/services)
4. UI labels/cards/sections updated
5. Session closed
